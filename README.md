# 浏览器人工验证交接

[新手逐步使用指南](USER_GUIDE.md) · [用途与适用人群介绍](INTRODUCTION.md)

`local-browser-human-handoff` · 独立技能仓库 · MIT

适合：使用浏览器助手、但需要本人扫码/登录/验证的用户

## 解决什么问题

把 AI 可做的准备与本人必须做的验证分清，登录回来后继续验证原任务，而不是把“登录成功”当作业务完成。

## 安装

无脚本依赖，不需要 pip 安装任何东西：本技能是流程与模板。

```sh
# 可选：校验交接单是否符合要求
python scripts/check_handoff.py templates/HANDOFF_STATUS.json
```

需要宿主（WorkBuddy/浏览器 Agent）提供浏览器操作能力。

## 快速开始

没有脚本依赖；需要宿主提供可用的浏览器操作能力。

阅读 [SKILL.md](SKILL.md)，再按 [交接示例](examples/handoff.md) 和 [状态模板](templates/HANDOFF_STATUS.json) 执行。

## 输入与输出

**输入**：目标页面、要完成的具体任务、当前遇到的登录/验证阻塞。不要提供密码、Cookie、令牌或浏览器档案。

**输出**：明确的人工动作、返回后的页面检查、原任务是否完成的证据，以及必要时的 BLOCKED 状态。

## 本次完善

已补：补交接请求、状态模板和完整演示，说明浏览器不同会话的限制与返回后的验证顺序。

## 适用用户

**适合：** 自动化流程卡在登录、验证码、二次验证时，需要把现场整理成一份人能接手的交接单的人；
有团队分工（机器跑前半段、人接后半段）的运营。

**不适合：** 想自动过验证码、自动登录的人——本技能明确不做认证动作；
期待工具代为点击确认的人。

## 当前限制

它检查记录是否完整，不能独立观察浏览器；实际登录、验证码和业务结果仍需本人或获准的浏览器工具确认。

## 验证与使用注意

这是流程型技能，没有可执行程序或程序单元测试。使用示例用于交接演练，不证明任何真实网站的认证已成功。

示例数据和图片均为合成演示，不是真实客户、交易、销量或模型成绩。不要提交真实凭据和私有输入。

## 第二轮：交接后的完成条件检查

增加可运行的交接状态检查器：登录后页面可见只能恢复原任务，声明任务完成必须附时间、结果链接和观察结果。

在仓库根目录运行：

```sh
python scripts/check_handoff.py templates/HANDOFF_STATUS.json
```

新增工具的输入字段见脚本参数与 examples/。快照示例采用固定日期，过期后正常返回 HOLD；需要检查新采集的页面时填写真实带时区的采集时间，不要改日期伪装新证据。
